# Data and privacy

AxDeck reads only the sign-in state and usage records that apps already keep. It never changes, renews or ends their sign-ins, never uploads conversations, and collects no usage data. The clipboard history, the file transfer, the system monitor and device batteries use their data only on this PC.

## Data read

| Tool | Quota | Tokens and cost |
| --- | --- | --- |
| Claude | Reads the Claude Code sign-in (`%USERPROFILE%\.claude\.credentials.json`), or the Claude desktop app's sign-in when that is unavailable, and asks Anthropic for the account usage. When the account belongs to several organizations (a personal Pro and a Team, for example), each is asked with the sign-in the desktop app keeps for it. Each row can turn off "Fetch quota online": such a row reads no sign-in and sends nothing, and shows only the quota the Claude desktop app recorded on this PC (`plan-usage-history.json`) | Reads the local Claude Code session records (`projects\**\*.jsonl`); regular chats in the Claude desktop app are not included |
| Codex | Reads the sign-in in `%USERPROFILE%\.codex\auth.json` and asks OpenAI for the account usage; if that fails, shows the quota from the session records and marks it as possibly out of date | Reads the local session records (`sessions` and `archived_sessions`) |
| Antigravity | Reads from the local service of the running Antigravity desktop app (127.0.0.1 only) | Reads the local conversation databases of the desktop app and the CLI under `%USERPROFILE%\.gemini` |
| Cursor | Reads the Cursor sign-in from `%APPDATA%\Cursor\User\globalStorage\state.vscdb` in read-only mode and asks Cursor for the account usage | Asks Cursor for the account usage details, including usage on other devices |
| Grok Bot | Reads the Grok Bot desktop app's own sign-in (`%APPDATA%\Grok Bot\sand-secrets.json`) and asks Cursor for that account's weekly allowance. Each row can turn off "Fetch quota online": such a row reads no sign-in and sends nothing, and shows only the weekly allowance the Grok Bot desktop app cached on this PC (`%APPDATA%\Grok Bot\sand-client-persistence`) | Not available |
| ZCode | Reads the ZCode sign-in and asks for the Coding Plan, Start Plan and MCP daily limits | Reads the local request records (`%USERPROFILE%\.zcode\cli\db\db.sqlite`) |
| DeepSeek Harness | Reads the DeepSeek Harness sign-in (`%USERPROFILE%\.dsh\.credentials.yaml`) and asks the DeepSeek platform for the account balance and total cost; without a signed-in account, uses the API key saved there to ask for the balance | Reads the local session records (`%USERPROFILE%\.dsh\sessions`) |
| Kimi Code | Reads the Kimi Code sign-in (`kimi-code.json` in `%USERPROFILE%\.kimi-code\credentials\`, or `kimi-code-env-…json` for the international site) and its service address and site settings (`config.toml` and the optional `region` file), and asks the chosen site (api.kimi.com or api.kimi.ai) for the plan quota and membership level; never renews the sign-in or changes any Kimi Code file | Reads the local session records (`%USERPROFILE%\.kimi-code\sessions`) |
| OpenCode | Reads the OpenCode Console sign-in from the OpenCode database (`%USERPROFILE%\.local\share\opencode\opencode.db`) in read-only mode, or without one the API key in `auth.json` in the same folder, and asks opencode.ai for the OpenCode Go allowance; never renews the sign-in or changes any OpenCode file | Reads the model request records in the same database, in read-only mode |
| Zhipu GLM, Z.ai GLM, DeepSeek, Kimi Code API, OpenCode Go, OpenRouter, New API, Sub2API, Custom | Uses the key and site address entered in settings; a Kimi Code API key is sent only to api.kimi.com and api.kimi.ai, and its quota is not written to `kimi-quota.json`; an OpenCode Go key is sent only to opencode.ai; an OpenRouter key is sent only to openrouter.ai. The key goes only over HTTPS or to this PC; a New API, Sub2API or Custom source with "Allow HTTP" on also sends it over HTTP, in plain text | Not available |

- When `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `ZCODE_HOME`, `DSH_HOME` or `KIMI_CODE_HOME` is set to an absolute path, that folder is read instead. OpenCode's database is found from `XDG_DATA_HOME` and `OPENCODE_DB`.
- These account APIs and local data formats are not stable public interfaces. When they cannot be read, the panel shows the actual status and never makes up numbers.

## Files stored on this PC

All files are stored in `%LOCALAPPDATA%\AxDeck` (the screenshots excepted: those go into your pictures folder):

| File | Contents |
| --- | --- |
| `settings.json` | Settings; no sign-in tokens or API keys |
| `services.json` | The services and tools page's tunnel entries, SSH hosts and BGE-M3 model path, kept on this PC only and never part of a published package; you write and edit it yourself |
| `secrets.dat` | API keys you entered, encrypted by Windows for the current user |
| `model-prices.json`, `manual-model-prices.json` | Updated model prices, and prices you added |
| `official-prices.json` | Prices of the model makers' own endpoints from OpenRouter, only for the models your records use and for Kimi K3, K3.1 Pro and K3.1 Pro Highspeed, which Kimi Code costs need. Without this file, the `moonshot-prices.json` saved by earlier versions is read |
| `claude-quota.json` | The last Claude quota read online (shares, reset times and the plan name), so per-model quotas such as Fable still show after a restart while the account API is rate limited; no sign-in token; the account and organization are recorded only as one-way hashes of their ids (never the ids themselves), one reading per organization, and the file is used only while the same account is signed in; not used once older than 7 days, deleted when the sign-in is rejected or removed |
| `kimi-quota.json` | The last Kimi Code quota read online (shares, reset times, extra usage and the membership level), so it still shows, also after a restart, while the sign-in has expired or the API is temporarily unavailable; no sign-in token or other account details; the account is recorded only as a one-way hash of its id together with the service address (never the id itself), and the file is used only while the same account on the same site is signed in; not used once older than 7 days, deleted when the sign-in is removed or the account has no Kimi Code plan |
| `update-prompt.txt`, `updates\` | The last version you were told about, and downloaded installers or portable zips (while a portable copy updates, also the extracted new version) |
| `cursor-prices.json` | Readings of a merged Cursor plan's weekly included usage (the amount and the tokens of each kind), used to estimate costs on that plan |
| `apple-music-lyrics.json` | Which lyrics each Apple Music song was matched to, used when the song plays again after a restart |
| `usage-history.json` | Each quota's used share today with the time it was read, drawn as the line behind the quota bars; at most one sample every 10 minutes, kept for 30 days. No token counts, account, conversation or text |
| `traffic-today.json` | Today's disk read, disk write, network download and network upload byte counts, with the system counter readings and the date they belong to; starts over at local midnight |
| `focus-timer.json` | The focus timer's length, seconds left and end time, so a countdown carries on while the panel is closed or across a restart |
| `command.txt` | The command a second AxDeck process leaves for the running one (from an `axdeck://` address, for example); it is deleted as soon as it is read, and holds only the command's name and its argument |
| `shelf.dat`, `shelf\` | The clipboard history, the file transfer's file paths and the categories of both, and the copied pictures (one file each), all encrypted by Windows for the current user. Ordinary clipboard entries are cleared when AxDeck exits (after an exit that did not clear them, at the next start); what is in Favorites or in a category set to be kept stays until you delete it |
| `themes\` | Custom panel theme files |
| `sensor-stops.json`, `sensor-pending.json` | The system monitor readings stopped because the PC froze (the drive or graphics adapter model, the board model and BIOS version), and the readings under way, so a reading that froze the PC is found at the next start; a record is removed when the reading is turned on again in the settings |
| `crash.log` | Error records; cleared when it exceeds 1 MB |
| `logs\bge-m3.log` | The output of the local `llama-server` that the services page starts, so a failed start leaves a trace |
| `logs\axtv-emulator.log` | The output of the local `emulator.exe` that the services page starts, for the same reason |

## Network and security

- Connects only to: each tool's official APIs, sites you enter in settings, the OpenRouter model list and the endpoint lists of the models your records use (model prices; only the model name is sent), lyrics services (LRCLIB, NetEase Cloud Music, QQ Music, KuGou Music), the cover addresses players provide, and GitHub Releases (updates; with enhanced sensors turned on, the sensor service and PawnIO's official modules).
- Claude desktop data folders include `%APPDATA%\Claude`, the Store paths `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude` and `%LOCALAPPDATA%\Packages\AnthropicPBC.Claude_*\LocalCache\Roaming\Claude`, and `%LOCALAPPDATA%\Claude-Data\<install>`.
- Sign-in tokens are used only in memory and never written to disk; the sign-in caches of the Claude and Grok Bot desktop apps are decrypted in memory with Windows encryption for the current user.
- Custom scripts run in a sandbox with no access to files, processes or .NET objects; see the limits in [Supported tools](ai-tools.md#custom-script).
- With "Show today's traffic" on, AxDeck reads all disks' and network adapters' cumulative counters in the background and adds the day's growth to `traffic-today.json`; only the four byte counts are stored — no address, host name or packet content — and nothing is uploaded.
- Quota curves record only each quota's used share from the readings already taken, to draw the line behind the bars; no file is read for them beyond the sources in the table above. Deciding whether a tool is working reads only the modification times of its session records, never opening or reading them.
- A clipboard picture is analyzed only when you choose "Read the picture…" from its menu: its QR code is decoded on this PC, and its text read by the recognizer Windows ships (`Windows.Media.Ocr`); neither goes online, and neither the picture nor the text leaves this PC. Making a QR code from text happens on this PC too.
- The output button on the music page reads only the names and states of this PC's playback devices to list them; Windows' audio service makes the switch, and AxDeck keeps no device list and changes no audio setting.
- The system monitor's readings, temperatures and drive space included, are read and shown only on this PC, never saved or sent. Drive space comes from each lettered volume's file system, and the physical drive a volume lies on from Windows' volume information. By default temperatures come from interfaces built into Windows: the ACPI thermal zones in the performance counters for the CPU, the data the graphics driver reports for the GPU (or, where the graphics kernel gives none, the interfaces NVIDIA's, AMD's and Intel's drivers ship), and each drive's own report, asked for with the drive opened without read or write access. No administrator rights or drivers are needed. A running HWiNFO (with shared memory on) or LibreHardwareMonitor (with its remote web server on; only localhost:8085 is contacted) is also read for the CPU's temperature and power. With [enhanced sensors](enhanced-sensors.md) turned on, the CPU's temperature and power are read from the processor by AxDeck's sensor service through the PawnIO driver.
- The whole machine's power draw and this PC's own battery are likewise read and shown only on this PC, never saved or sent, and only while the system monitor page is open or the collapsed row chooses the reading: processor power comes from Windows' Energy Meter performance counters, NVIDIA graphics power from the nvidia-smi.exe the graphics driver ships (started by AxDeck only while the adapter is working and the page or the row shows the power, ended with AxDeck; not read while the adapter is idle, so a sleeping discrete GPU is not woken), the battery's charge, rate and capacities from Windows' battery interface, and the power mode and Battery saver from Windows' power API. No administrator rights or drivers are needed.
- The frame rate is not read by default. Turning on "Show the frame rate" needs the current user in Windows' Performance Log Users group, which Windows asks an administrator to confirm once; after that only the events of the program in front drawing its frames are read, to work out the frame rate and show the program's name. Nothing is saved or sent.
- Device batteries are read only while the device batteries page, the collapsed "Device batteries" reading or Settings › Display and devices shows them; nothing is saved, sent or fetched online. Bluetooth devices' levels come from the values Windows reads itself (as Windows Settings › Bluetooth & devices shows them), or from the device's Bluetooth battery service; devices on a 2.4 GHz receiver or a cable are asked read-only questions over their HID interfaces; Xbox controllers are read through Windows' game controller interface; AirPods and Beats only while connected, from their Bluetooth advertisement when close by. The supported brands are listed in [Supported devices](devices.md). Nothing is paired, disconnected or changed on any device or in Windows, and no administrator rights or drivers are needed. Devices whose order, name, colors or placement you change in the settings are kept in `settings.json` (their identifier, name, kind, the name you gave them, their colors and where they show).
- The clipboard history reads the text and pictures on the system clipboard only while "Record the clipboard" is on, and keeps them on this PC with the process name of the app they were copied from; nothing is uploaded. Copies from the apps under "Apps not recorded", and copies that an app marks as not to be kept in clipboard history, as password managers do, are not recorded. The file transfer keeps only each file's path and reads its icon, size and modified time to show them; it never reads a file's contents or copies a file. See [Clipboard and file transfer](clipboard.md).
- The desktop page reads only what is in the desktop folders, and reads it mostly read-only: your own desktop and the shared desktop all accounts see are both listed entry by entry (names, kinds, modified times and such metadata, never a file's contents) to draw the icons; drawing them also reads the icon a shortcut or executable carries. While the page shows, file system watchers keep an eye on those two folders (listening for change events only, never reading contents), and the watchers are let go when the panel collapses. Putting things on the desktop — dragging in, pasting, renaming — writes only to your own desktop folder; deleting goes through the system shell to the recycle bin. Reordering by dragging, besides the read-only folder listing above, asks Explorer's desktop icon list for each item's name and position (for which a small block of memory is allocated inside explorer.exe and released as soon as the read is done), and after you drop, writes the new coordinates back to that same list (`LVM_SETITEMPOSITION`); Explorer persists the positions itself, and AxDeck never reads or writes its position record. Neither touches a file's contents nor goes online. "Take over the desktop while running" reads and writes one registry value (`HideIcons` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced`), the same switch Windows' "View › Show desktop icons" uses. The context and properties menus call Windows' shell components (COM); what a menu does is what you choose, and AxDeck starts no operation of its own. Nothing goes online. See [Desktop page](desktop.md).
- The sound behind the equalizer is analyzed only in memory and never saved.
- The services and tools page works on this PC and with your own domains only: the tunnel part reads the local cloudflared and SSH setup and connects only to the sites and NAS you list in `services.json` on this PC, the BGE-M3 part reads and starts the local `llama-server` on 127.0.0.1:8091, and the emulator part only talks to the Android SDK on this PC (`emulator.exe`, `adb.exe`) and does not go online. Neither the repository nor a published package carries a host name, a port or a path from anyone's machine; those are read from `services.json` and never leave the PC. The model stays on this PC and no credential or token is stored. Turning on "Start with Windows" for BGE-M3 writes one value for the current user (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\AxDeckBgeM3`) holding the full `llama-server` command line, including the server and model paths on this PC; turning it off deletes it. See [Services and tools](services.md).
- The `axdeck://` address is registered for the current user only (`HKCU\Software\Classes\axdeck`) and opens AxDeck itself; it carries no other program and handles no one else's content. When a start by address or command line finds an AxDeck already running, the new process writes the command to `command.txt` and exits at once, and the running one reads and deletes it; both stay on this PC and nothing goes online.
- The focus timer is kept on this PC only (`focus-timer.json`) and is never uploaded; no request is sent when it ends, only a Windows notification.

## NetEase Cloud Music full control

- Full control needs NetEase Cloud Music to open a local debugging port. When enabled from AxDeck, the port is 127.0.0.1:21631.
- While the port is open, other programs on this PC and web pages in a browser may use it to control NetEase Cloud Music and read its page content and sign-in state.
- Before connecting, AxDeck checks that the port listens only on this PC and belongs to NetEase Cloud Music, but this cannot remove the risk of the port itself.
- Through this port, AxDeck reads the song that is playing, its progress, the playback mode and whether the current song is liked, and has NetEase Cloud Music act only when you select a control. When you select the heart, NetEase Cloud Music itself adds the song to, or removes it from, the liked songs of your account. To show the heart, AxDeck takes only two results, whether NetEase Cloud Music is signed in and whether the current song is liked; it neither reads nor keeps your account details or your other songs.
- When enabled just once, the port stays open until NetEase Cloud Music is started again the normal way: quitting AxDeck, or a full control connection that fails (AxDeck then only reads what is playing), does not close it.
- With the Always enable full control switch on, AxDeck changes 2 places in the `libcef.dll` in NetEase Cloud Music's install folder, after which every start opens this port. The port stays available until you turn Always enable full control off in Settings › Players › NetEase Cloud Music and NetEase Cloud Music starts again, or an update replaces the file; quitting AxDeck does not close it.
- Turn it on only in an environment you trust.

## KuGou Music full control

- Full control changes 9 bytes of `libcef.dll` in KuGou's installation folder. After that, KuGou opens a local debugging port at 127.0.0.1:12233 each time it starts.
- While the port is open, other programs on this PC may use it to control KuGou and read its page content and sign-in state.
- Before connecting, AxDeck checks that the port listens only on this PC and belongs to KuGou, but this cannot remove the risk of the port itself.
- Through this port, AxDeck reads only the song that is playing, the playback state, progress, length, cover address and the song's hash, and has KuGou act only when you select play, pause, previous or next. It neither reads nor keeps your account details.
- The song's hash and length are sent to KuGou's lyrics service to look up the song's lyrics.
- The port stays until KuGou starts again after Always enable full control is turned off in Settings › Players › KuGou Music, or a KuGou update replaces the file; quitting AxDeck does not close it. Turn it on only in an environment you trust.
