# 软件更新

「软件更新」页把整台机器上已安装应用的可用更新集中列在一起，一项一项地升，不必挨个打开应用、逐个点「检查更新」。

这一页只做两件事：读出这台机器上装了什么、问一下有没有新版，然后按你的点击去升级。它不会自动安装任何东西，也不替你接受任何许可协议。

## 页面上有什么

- 顶部状态行：`共 N 项可更新` 与上次检查的时间；正在检查时换成「正在检查…（首次约需 1～2 分钟）」。右侧的「立即检查」可以随时手动查一次。
- 每一行一个应用：名称、`当前版本 → 可用版本`、来源标记（`WinGet` 或`厂商`），右侧是操作按钮。
- 行数多于页面高度时可以滚动，用鼠标滚轮上下翻。

## 数据从哪里来

三层来源各自独立，一层失败不影响其余：

| 层 | 来源 | 提供什么 |
| --- | --- | --- |
| WinGet | `winget upgrade` 的输出 | 已安装、且 WinGet 知道有新版的包：ID、当前版本、可用版本。这是主干，覆盖绝大多数开发工具 |
| 内置映射表 | 随应用发布的 `apps.json` | WinGet 认不出、但有公开版本接口的常见应用（VS Code、Firefox、GitHub CLI、DBeaver、Obsidian）的最新版本，向 GitHub Releases 或厂商接口询问 |
| 已安装清单 | Windows 的卸载信息（注册表） | 只用来枚举这台机器上装了什么：名称、版本、可执行文件。它不提供「有没有新版」 |

映射表是一份可扩展的清单：某个应用有厂商公开的版本接口时，加一条就能补上，不必依赖整个第三方软件商店。

## 检查的节奏

- 打开「自动检查更新」后，AxDeck 启动约 90 秒检查一次，之后每 6 小时一次。
- 检查失败时按 15 分钟、1 小时、4 小时重试；上次是失败的话，重启 AxDeck 后也先等 15 分钟，不会一启动又跑一遍。
- 「自动检查更新」开着时，面板打开这一页若发现上次结果超过 12 小时或根本没有，会在后台立刻补一次；结果还新就直接显示上次的列表。
- 每次检查都要调用一次 `winget`，首次约需 1～2 分钟，全程在后台，不占面板。
- 结果存在 `%LOCALAPPDATA%\AxDeck\software-updates.json`，重启后仍能立刻显示上次的列表与检查时间。

## 更新一项

- 来源是 `WinGet` 的项，按钮是「更新」：在后台静默升级这一个包，按钮变成「更新中…」，成功后变成「已更新」，并自动重新检查一次。
- 只有下载页的项，按钮是「下载」：用系统浏览器打开该应用的下载页，剩下的由你手动完成。
- 升级失败时按钮变成「重试」，再点一次就会重新升级。
- 升级逐项进行，不并发：WinGet 自己有锁，同时跑会互相失败。
- 不会全自动升级——每一项都由你点。

## 空态

三种情况分开显示，不能互相代替：

- `未检测到 WinGet`：这台机器没有「应用安装程序」（App Installer），装上之后才能检查。
- `未检测到可更新的应用`：检查成功，当前没有可更新的项。
- `正在检查…`：还没有结果，首次约需 1～2 分钟。

检查失败时显示失败原因的原文，并保留上一次的列表——「查不到」不会被显示成「没有更新」。

## 版本怎么比

- 版本号按其中的数字分段比较：`b10107` 与 `b12602` 能正确判出新旧，`18.4-2` 与 `18.7-2`、`2.1.25156` 与 `2.2.26323` 同理。
- 映射表报回来的版本号必须确实比已装版本新才会列出；读不到、或在响应里找不到版本字段时，这一次当作没问到，不会猜一个版本号，也不会因此说「已是最新」。

## 设置

设置 › 软件更新：

- **自动检查更新**（默认开）：关闭后不再定时检查，页面里仍可手动点「立即检查」。
- **立即检查**：与页面右上角的按钮是同一个入口，结果也是同一份。
- **尺寸**：这一页的宽高在设置 › 展开外观里调整。

## 限制

- WinGet 只认它收录的包；未被收录的应用不会出现在这一层。映射表目前只有几个常见应用，其余应用既不会显示「可更新」，也不会显示「已是最新」。
- `winget upgrade` 不接受指定源，也无法在一次调用里排除不可达的源（例如 msstore），所以检查需要 1～2 分钟，无法压缩到几秒。
- AxDeck 不会替你接受任何源协议；只有 WinGet 明确要求包协议时，才追加 `--accept-package-agreements` 重试一次。
- 本页读取了哪些数据、向哪些地址发出请求，见[数据与隐私](privacy.md)。
