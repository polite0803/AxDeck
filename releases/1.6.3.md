This release fixes the software updates page entries whose upgrades kept failing.

Fixed
- Upgrades now run one at a time. Selecting several items queues the rest ("Queued…") instead of starting them all together: WinGet holds a lock, and a dozen downloads running at once saturated the link, so large installers such as CMake, LLVM and WinFsp timed out every time.
- A package installed by MSI, PowerShell 7 among them, has no winget package id in its installed record, so `winget upgrade --id` answered "No app found matching input criteria" and the update never ran. AxDeck now retries with the name the list shows, which winget does match.
- A failed upgrade now reports the failure line from winget's output rather than its first line ("Found PowerShell"), and that reason stays in the status line after the automatic recheck.

这个版本修好「软件更新」页上几种始终升级不成功的项。

修复
- 升级改成一次只跑一项：连点几项时，其余的按钮显示「排队中…」，而不是一起开始。WinGet 自己有锁；十几个包同时下载会把带宽打满，CMake、LLVM、WinFsp 这类大安装包每次都因此超时。
- PowerShell 7 这类用 MSI 装的包，已安装记录里没有 winget 包 ID，`winget upgrade --id` 只会答「找不到与输入条件匹配的已安装程序包」，永远升不动。现在会自动改用列表里显示的名称重试，winget 认得这个名字。
- 升级失败时状态行给的是 winget 输出里的失败原因，不再是第一行「已找到 PowerShell」这类过程信息；自动重新检查之后，这句原因也继续保留。
