This release fixes the two ways the Desktop page's mouse was still not working after 1.3.2: a double click opened nothing, and the item's system menu showed but did nothing when a command was chosen. They were two unrelated faults.

Fixed
- A double click on a Desktop page icon selected it and stopped there; only a single click to select worked. The open check read the click count from the release, but WPF sets that count on the press: the second press reports 2, the release that follows it reports 1 again. The condition never held, so an item was never opened. The count is taken from the press now and used by the release that belongs to it, so a double click opens what a double click on the real desktop opens.
- Choosing a command from an item's system menu did nothing: the menu appeared, the item was highlighted, and the file was left exactly as it was. The chosen command is handed back to the shell in a structure the shell reads by field position, and the structure was declared with its fields out of order — 48 bytes, with the window handle where the flags belong. The shell saw the wrong size, refused the call and dropped every command. It is declared in the order the Windows SDK gives, 56 bytes, and a check pins the size and the offset of every field so the order cannot slip again.

本次发布修好「桌面」页上 1.3.2 之后仍然失效的两处鼠标操作：双击打不开任何东西，以及右键菜单能弹出来、选中命令却什么也不做。这是两个互不相关的缺陷。

修正
- 在「桌面」页的图标上双击，只是选中了它，到此为止；只有「单击选中」是好的。打开一项的判断读的是「抬起」事件里的点击次数，而这个数是 WPF 在「按下」时给的：第二下按下的数是 2，紧跟着的抬起又变回 1。条件因此永远不成立，一项也打不开。现在这个数在按下时记下、交给属于它的那次抬起使用，双击打开的就是真实桌面上双击会打开的东西。
- 在某一项的右键菜单里选一条命令，什么也没发生：菜单弹出来了，项也高亮了，文件却原样不动。选中的命令要装进一个结构体交回系统执行，而系统是按字段的位置读它的；这个结构体的字段顺序写错了——只有 48 字节，窗口句柄还占了标志位该在的位置。系统读到的大小不对，整个调用被拒绝，所有命令都被丢掉。现在按 Windows SDK 给出的顺序声明，56 字节，并加了断言把每个字段的大小和偏移钉死，这个顺序不会再悄悄错回去。
